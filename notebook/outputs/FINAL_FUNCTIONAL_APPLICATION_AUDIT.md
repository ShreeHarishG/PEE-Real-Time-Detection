# EdgeVision V3-HN Functional Application Audit

## Files Changed
- `backend/app/main.py`: Added endpoints for video upload (`/api/v1/videos/upload`), job processing (`/api/v1/jobs/{video_id}/process`), job status (`/api/v1/jobs/{job_id}`), job progress (`/api/v1/jobs/{job_id}/progress`), job termination (`/api/v1/jobs/{job_id}/stop`), and zone updating (`PUT /api/v1/zones/{zone_id}`). Integrated `subprocess` to manage the ML pipeline execution.
- `backend/app/schemas.py`: Added `ZoneUpdate` schema to support partial updates for Zones (polygon, required PPE) and `JobProgressUpdate`.
- `src/pipeline.py`: Added `--job-id` parameter. Implemented dynamic polling of zone configuration and polygon. Added OpenCV `pointPolygonTest` to ensure violations are only generated for subjects inside the active safety zone. Added job progress telemetry API calls.
- `frontend/src/app/page.tsx`: Rewritten entirely to transition from a static mock dashboard into a fully functional Next.js application. Integrated interactive video upload, job lifecycle controls, interactive SVG polygon drawing over the MJPEG stream, and dynamic violation rendering.

## Known Limitations
- If multiple users start processing simultaneously on different videos, the MJPEG stream (`latest_frame.jpg`) and `outputs/annotated_output_functional.mp4` file will currently experience collisions because they share a static path. This is acceptable for a single-camera edge setup but should be UUID-separated for a multi-tenant cloud environment.
- The interactive zone drawing assumes the live MJPEG stream matches the native aspect ratio. Shrinking the browser window might require users to re-draw if resizing isn't fully proportional.
